# README: Building Firebase Apps in Google Antigravity IDE

## 📖 Overview
**Building Firebase Apps in Google Antigravity IDE** is a step-by-step guide to developing, testing, and deploying Firebase applications locally using Google's agent-first Antigravity IDE. It covers two starting points — migrating an existing Firebase Studio project, or starting a new codebase from scratch — and carries both through to a production-grade workflow with Cloud Firestore, the Local Emulator Suite, security rules unit tests, and automated deployments.

The guide was written against the official Antigravity and Firebase documentation as of September 2026 and includes a Sources section linking to every page it was verified against.

## 🗂 Contents of the Guide
The main document (`firebase_antigravity_guide.md`) is organized into eleven sections:
1. **Local Runtime Environment Setup** - Node.js 20+ installation for Windows, macOS, and Linux; Firebase CLI install and login; JDK for the emulators.
2. **Install Antigravity and Connect It to Firebase** - Installing the IDE, enabling the Firebase Bundle (agent skills), installing the Firebase MCP server (agent tools), and how the agent pane works.
3. **Path 1: Migrate an Existing Firebase Studio Project** - Exporting from Studio, converting the project with `@fbs-to-agy-export` or the manual `studio:export` CLI, reconnecting to your existing Firebase project, and republishing to your live URL.
4. **Path 2: Start a New Project in Antigravity** - Creating a Firebase project, scaffolding Next.js / Vite / Angular, and initializing Firebase either through the agent or manually with `firebase init` and the web SDK.
5. **Working With the Agent** - Prompts that do real work: rules audits, emulator verification, pre-deploy checks, and publishing.
6. **Choose Your Deployment Path** - App Hosting vs. static Firebase Hosting, when each fits, and the config files for both.
7. **Production Firestore Security Rules** - A rules blueprint with authentication, ownership, and input validation helpers.
8. **Local Emulator Seeding** - A seed script and snapshot workflow so the emulator boots with realistic data every time.
9. **Firestore Rules Unit Tests** - A Jest + `@firebase/rules-unit-testing` harness that runs your real rules against the emulator.
10. **Continuous Deployment** - App Hosting's built-in GitHub rollouts, or a GitHub Actions workflow for static Hosting with correctly scoped service account roles.
11. **Next Steps** - Where to go once the basics are running.

## ⚠️ Important Notes
* **Deployment path matters.** Apps generated by Firebase Studio's App Prototyping agent are Next.js apps on App Hosting. Forcing them into a static export will break server-side features. Read Section 6 before touching hosting config.
* **Rules deploy separately from App Hosting rollouts.** Pushing to your live branch does not push `firestore.rules`. Section 10 covers this.
* **Service account keys are credentials.** The GitHub Actions path stores a JSON key as a repository secret. Grant it only the roles listed in Section 10, never Owner or Firebase Admin.
* **Firebase Studio is sunsetting.** New workspace creation was disabled June 22, 2026; the editor shuts down March 22, 2027. Deployed apps keep running.

## 🚀 How to Use
Open `firebase_antigravity_guide.md` in any Markdown viewer, text editor, or code editor (such as VS Code, Obsidian, or GitHub's built-in preview). Work through Sections 1 and 2 first, then follow **either** Section 3 (migrating) **or** Section 4 (new project), and continue from Section 5 onward.
